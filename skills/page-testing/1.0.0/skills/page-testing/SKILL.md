# page-testing — 项目扫描编排（主 agent 剧本）

主 agent 按本剧本编排：自己跑准备，逐页派 `agent-browser` 子代理扫描，收结果汇总出报告。
子代理只扫一页；所有跨页工作（对账、报告）在主 agent 侧。
通用浏览器操作工 `agent-browser` 不绑定本插件，任何需要操控浏览器的任务都可以派它。

## 生命周期

```
setup（主agent，一次）→ 派单扫描（子代理 × 页）→ 对账汇总（主agent）→ 报告 → （修复后）修复验收（派单附 fix-verify.md + 服务日志路径 + 目标版本号）
```

### 1. 准备

读同目录 `setup.md` 执行一次。产出：页面路由清单 + 项目画像摘要 + 测试数据说明 + 竞品清单 + 任务清单。

### 2. 派单

对每个页面派一次子代理。**默认 3 个独立浏览器实例并行**（每实例独立 CDP 端口 + 独立 user-data-dir，凭据各自登录——同 profile 多标签会互抢登录态，禁止）。N 可配：页面 30+ 或后端扛得住可升；SSE/LLM 重的页面（chat/report 类）错峰派单，避免压垮被测应用的推理管道污染 findings。graph/canvas 类页面允许长时间零落盘，静默 ≠ 挂起：判断子代理生死看台账更新，不看请求流：

```
Agent(subagent_type="agent-browser", prompt = 以下五样, 环境变量: 端口+profile)
  ① 页面 URL
  ② 项目画像摘要 + 测试数据说明 + 竞品清单（review 分支的叛逃者视角需要）
  ③ 登录凭据（按需让子代理自行登录）
  ④ 分支协议全文：audit 模式贴本目录 audit.md，review 模式贴 review.md
  ⑤ 扫描协议全文：本目录 scan-protocol.md（台账 + DOM 12 条 + 扫描返回格式）
```

- 完整扫描 = 每页派两次（audit + review）；单分支模式只派一次
- 另派**一个任务流子代理**（唯一跨页的，需浏览器状态连续）：prompt = `audit.md` 中「任务流」一节 + 任务清单 + 画像 + 凭据 + scan-protocol.md，单独跑
- 非扫描的浏览器任务：直接派 `agent-browser`，只给任务 + URL + 凭据，不带 ④⑤
- 回归验收（用户给了上次报告路径时）：派单 prompt 附基线中该页的 P0/P1 问题清单，子代理重点复核这些项；汇总时逐条判定「已修复/仍在/新增」填入报告

### 3. 收结果

子代理返回固定格式（findings / ledger / dom_hits / 声明 / 截图）。

- pending > 0 → 重派该页一次；仍不为 0 → 报告顶部标注中断原因
- 返回内容为空（跑了很久却无输出）→ SendMessage 催收重交（r6 实战有效：agentId + 要求补交 findings/ledger/dom_hits/声明）
- 各页 findings 边收边追加写入 `findings/{页面}-r{N}.md`，不要等最后汇总；跨页对账在全部收齐后做
- 任务流返回必须带回功能闭环清单处置状态（verified/skipped+原因）；**有未处置项就不出报告**，重派任务流
- 各页 ledger JSON 与截图路径随返回交付，汇总进报告

### 4. 跨页对账（主 agent 做）

把各页返回的统计数字记入 `metrics-ledger.json`（指标名+值+页面），全部收齐后核对：
① 同名指标跨页一致 ② 总数 = 各分项之和 ③ 统计数字 = 对应列表实际行数 ④ 子状态数量之和 = 总数。
矛盾逐条记「数据不一致」P1 以上。文案/格式一致性同理：各页记录值，此处比对。

### 5. 报告

读 `report-template.md` 套模板输出。只描述问题，不写修复方案。

## 边界与约定

| 场景 | 处理方式 |
|------|---------|
| 需要登录 | 无凭据则跳过该流程，报告标注「未测试：需要登录」 |
| 扫描中断 | 已完成页面照常出报告，顶部注明"部分完成" |
| 耗时 | 10+ 页全面扫描约 10-20 分钟，提前告知 |
| 不改代码 | 不修改项目代码；可写入测试数据与权限配置，默认保留，报告标注写入位置 |
| 完整 vs 快速 | 完整模式逐页全部截图分析；快速模式只核心 3-5 页桌面端 |
| 真机/硬件依赖 | 手机卡外呼、定位采集、微信/小程序/美团等第三方推送、App 端页面——浏览器扫描本质不可达，报告必须列「不可覆盖类别」清单并逐项声明，不得沉默 |
| 延时策略生效 | 「自动清理 90 天」「敏感词拦截」「定时同步」等只能验证配置入口与提示文案，标注「未验证：需长周期观察」 |
| 无文档业务规则 | 项目画像/文档未声明则无法判断应有性；有矛盾线索按「字段间矛盾」记，否则标注「依赖业务规则，未覆盖」 |
| 后端缺数据 | 页面空 + 接口也空 = 记「待确认」并附接口返回值，不判 bug |
| 设计偏好类 | 「改颜色/删按钮/弹窗改面板」类主观诉求单列「改进建议」区，不计入缺陷数 |
