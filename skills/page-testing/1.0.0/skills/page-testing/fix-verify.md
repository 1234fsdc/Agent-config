# fix-verify — 修复验收专用协议（主代理派「修复验收」单时随 prompt 下发）

> 适用：bug 修复后的浏览器验收（区别于全页扫描）。每条都来自真实漏测事故，见括号内事故编号。

## 第 0 步：版本断言（防缓存假结果）

主代理派单时声明本次验收的**目标版本号**（每个改过的 JS/CSS 文件）。验收 agent 第一个动作：
`evaluate` 读 DOM 的 `script[src]`/`link[href]`，与声明逐一比对。**不符 → 整轮验收无效，立即返回「版本不符」**，不得进入任何测试。
（事故：修复后忘 bump 版本号，agent 拿缓存旧 JS 跑完验收报 FAIL——本轮发生 3 次。）

硬刷新用 `Page.reload(ignoreCache=true)`；页面 HTML 无版本号的（内联 CSS 改动），用 computed style 断言新规则生效（如 `getComputedStyle` 检查新增属性值）替代版本比对。

## 分层验证对照（改哪层验哪层 + 下游一层）

| 改动层 | 最低验收断言 |
|--------|-------------|
| 数据字段/API | API 响应**字段值**（非 200 状态码） |
| 渲染逻辑 | 渲染后的 **DOM 文本/属性**（非 API 返回值） |
| 交互行为 | 点击后**状态变化**（元素出现/消失/文本变更） |
| CSS 布局 | computed style + 改动区**特写截图**视觉自答 |

「上一层通过」不能替代下一层断言。（事故：字段名读错 severity/level，API 通过但 UI 显示数字。）

## 受影响面回归

修复验收 ≠ 只验 diff。改动事件/接口/字段/推送时，**grep 全部前端消费点**（事件名、字段名、端点），逐个列入验收清单回归。
（事故：改 progress 推送后，只验了新帧格式，没回归消费 progress 的既有 UI——计数口径偏差在相邻功能里存活。）

## 吞异常审计

改动逻辑位于 try/except 内的，验收时必须 grep 服务日志该文件名/函数附近的 WARNING/ERROR（派单时主代理附日志路径，通常 `logs/query_stdout.log`）。生成类字段为空的，先查日志再下结论「数据为空」。
（事故：followups 的 UnboundLocalError 被 except 吞掉，日志第一秒就写着答案。）

## 事件单源断言

改动涉及 SSE/事件/推送的：抓完整帧序列，断言同一节点/事件名在序列中只出现一次、计数/列表单调不回退、无中英双名混发。
（事故：新增一个 progress 推送源，与既有源混发致 UI 列表重复。）

## 负样本断言

文案/空态类修改至少验「有值/空值」两种数据形态；空值分支的文案**不得引用可能不存在的元素**（如「按上方一口价收取」出现在没有价格盒的页面）。

## 视觉特写自检

每处改动区域必须附**特写截图**（非全页），agent 对特写自答三个问题并写进返回：
① 有无元素重叠/文字被盖 ② 有无裁切/溢出 ③ 间距对齐是否正常。
全页截图不算数——特写才暴露「图标盖住一个字」级别的缺陷。
（事故：搜索图标叠住 placeholder 首字，全页截图 + DOM 断言全绿。）

## 视口矩阵（涉及布局/浮层/面板开关时必跑）

- 断点矩阵：读页面 CSS 的 media query 断点，在**每个断点两侧 ±50px** 各一档。
- **用户实际宽度**：主代理从用户截图/窗口推算的实际 CSS 视口宽，必测。
- 浮层/面板/抽屉类：跑「状态 × 视口」矩阵（开/关 × 每档），每格特写截图。
（事故：只测 1920/1024，用户的 ~1560 落在 flex 挤压分支临界溢出。）

## 返回格式

在 scan-protocol 标准返回之上，额外必含：
`版本断言: {文件: 版本, 全部相符}` / `分层断言: [每层结果]` / `日志审计: {grep 关键字, 命中数}` / `视口矩阵: {档位×状态, 每格 PASS/FAIL}` / `特写截图: [路径]`
