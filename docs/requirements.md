## 2. 需求定位

本项目采用“简单但完整”的实现方式：不做真实后端、不做数据库、不做复杂业务流程，只完成一个可以运行、可以演示、可以答辩的 Vue3 前端项目。

项目需要覆盖课程要求中的关键能力：

1. Vue3 基础语法和指令。
2. 组件化开发。
3. Vue Router 页面跳转。
4. Pinia 状态管理。
5. 表单、搜索、收藏、发布等基础交互。

## 3. 项目背景

校园中常见闲置书籍、电子产品、生活用品等二手物品。学生之间有交易需求，但信息发布在聊天群或线下渠道时较分散，不方便查找和管理。

本项目设计一个校园二手交易平台，用于展示二手商品、搜索商品、查看详情、收藏商品和发布闲置商品。项目重点不是做复杂商业系统，而是完整体现 Vue3 前端项目的基本开发流程。

## 4. 项目目标

项目完成后，应能演示一个完整用户流程：

1. 用户注册账号。
2. 用户登录系统。
3. 用户进入首页浏览商品。
4. 用户搜索或筛选商品。
5. 用户查看商品详情。
6. 用户收藏感兴趣的商品。
7. 用户发布自己的闲置商品。
8. 用户在个人中心查看收藏和发布记录。

## 5. 实现范围

### 5.1 本次实现

本次只实现前端功能，数据使用本地模拟数据和 localStorage 保存。

需要实现的功能：

1. 登录和注册。
2. 首页展示。
3. 商品列表浏览。
4. 商品搜索和分类筛选。
5. 商品详情查看。
6. 商品收藏和取消收藏。
7. 发布商品。
8. 个人中心。
9. 退出登录。

### 5.2 不实现内容

为保证项目简单可控，以下内容不在本次范围内：

1. 真实后端接口。
2. 数据库。
3. 在线支付。
4. 即时聊天。
5. 真实图片上传。
6. 管理员后台。
7. 商品审核流程。

这些内容可以在项目报告中作为后续扩展方向说明。

## 6. 页面需求

项目保留 7 个页面，数量不多，但能覆盖完整流程。

| 页面 | 路由 | 作用 |
| --- | --- | --- |
| 登录页 | /login | 用户登录 |
| 注册页 | /register | 用户注册 |
| 首页 | / | 展示推荐商品、分类入口和导航 |
| 商品列表页 | /products | 浏览、搜索、筛选商品 |
| 商品详情页 | /products/:id | 查看商品详情、收藏商品 |
| 发布商品页 | /publish | 发布闲置商品 |
| 个人中心页 | /profile | 查看用户信息、收藏商品、已发布商品 |

## 7. 功能需求

### 7.1 注册

用户填写用户名、密码和确认密码完成注册。

要求：

1. 用户名不能为空。
2. 密码不能为空。
3. 两次密码必须一致。
4. 注册成功后保存用户信息。
5. 注册成功后跳转到登录页。

### 7.2 登录

用户使用用户名和密码登录。

要求：

1. 用户名不能为空。
2. 密码不能为空。
3. 登录成功后保存登录状态。
4. 登录成功后跳转到首页。
5. 登录失败时显示提示信息。

### 7.3 首页

首页作为系统入口，展示平台主要信息。

要求：

1. 有公共 header。
2. 有公共 footer。
3. 展示推荐商品。
4. 展示商品分类入口。
5. 提供进入商品列表、发布商品、个人中心的导航。

### 7.4 商品列表

商品列表展示所有二手商品。

要求：

1. 展示商品名称、价格、分类、成色和简介。
2. 支持关键词搜索。
3. 支持分类筛选。
4. 点击商品可以进入详情页。
5. 没有搜索结果时显示空状态。

### 7.5 商品详情

商品详情页展示单个商品完整信息。

要求：

1. 展示商品名称。
2. 展示商品图片或默认占位图。
3. 展示价格、分类、成色、交易地点。
4. 展示商品描述。
5. 展示卖家名称和联系方式。
6. 支持收藏和取消收藏。
7. 未登录用户点击收藏时提示先登录。

### 7.6 发布商品

登录用户可以发布闲置商品。

要求：

1. 商品名称不能为空。
2. 商品价格不能为空，并且必须是数字。
3. 商品分类不能为空。
4. 商品成色不能为空。
5. 商品描述不能为空。
6. 发布成功后商品出现在商品列表中。
7. 发布成功后显示提示信息。

### 7.7 个人中心

个人中心展示当前用户相关内容。

要求：

1. 展示当前登录用户名。
2. 展示收藏商品。
3. 展示自己发布的商品。
4. 支持退出登录。
5. 未登录访问时跳转到登录页。

## 8. 组件需求

组件数量保持精简，只抽取重复使用或职责清晰的部分。

建议组件：

1. AppHeader：公共头部和导航。
2. AppFooter：公共底部。
3. ProductCard：商品卡片。
4. ProductFilter：搜索和分类筛选。
5. EmptyState：无数据提示。

不为只使用一次的简单区域单独创建组件，避免过度设计。

## 9. 状态管理需求

使用 Pinia 管理全局状态，保持简单。

建议只创建 2 个 store：

| Store | 作用 |
| --- | --- |
| userStore | 管理注册用户、当前登录用户、收藏商品 id |
| productStore | 管理商品列表和发布商品 |

状态需要同步到 localStorage，使页面刷新后用户状态、收藏记录和商品数据不丢失。

## 12. 验收标准

项目完成后需要满足：

1. 项目可以正常启动。
2. 7 个页面都能正常访问。
3. 页面之间可以通过 Vue Router 正常跳转。
4. 登录、注册、搜索、筛选、收藏、发布商品功能可用。
5. Pinia 用于管理用户和商品状态。
6. localStorage 能保留登录状态、收藏记录和发布商品。
7. 页面包含 header、footer 和主体内容。
8. 页面无明显布局错乱。
9. 浏览器控制台无主要运行错误。
10. 项目报告能够说明需求、设计、实现和总结。
